Errors and fixes (lessons learned — concrete examples)
-----------------------------------------------------
- Comptime/runtime @sizeOf usage:
  Symptom: compiler error complaining that a comptime-only value depended on runtime control flow when using `if (is_64) @sizeOf(...) else @sizeOf(...)` inside a bounds expression.
  Fix/Decision: compute the entry size at runtime in a separate statement:
      var nlist_entry_size: usize = 0;
      if (is_64) nlist_entry_size = @sizeOf(macho.nlist_64) else nlist_entry_size = @sizeOf(macho.nlist);
  Rationale: avoid selecting a comptime-only value in a runtime expression.

- ArrayList / field access confusion:
  Symptom: used `.len` on an ArrayList-managed struct (e.g. segmaps.len) which is invalid; the actual slice is in `.items`.
  Fix: use `segmaps.items.len` and iterate `segmaps.items[i]` or use the standard ArrayList API.

- LoadCommandIterator initialization:
  Symptom: left `index` uninitialized or initialized partially which caused next() to behave incorrectly (or be mis-initialized when using `undefined`).
  Fix: initialize the iterator explicitly: `var lc_it: macho.LoadCommandIterator = .{ .ncmds = ncmds, .buffer = lc_buffer, .index = 0 };` or assign fields explicitly when needed.

- Format string mismatch when printing booleans:
  Symptom: used `{b}` to print a bool with std.debug.print which caused a compile-time format validation error.
  Fix: format booleans as `{s}` with `if (b) "yes" else "no"` or convert to a string before printing.

- Alignment and pointer-casting pitfalls:
  Symptom: attempted to `@ptrCast` an unaligned slice directly into an aligned array type and ran into alignment/UB concerns.
  Fix: either use `[]align(1) const T` casting form or copy the small struct value into a properly aligned local before calling helpers that expect aligned pointers. In several places I used `@as([*]align(1) const macho.nlist_64, @ptrCast(...))[0..n]` to avoid alignment errors.

- Skipping unsupported variants (big-endian) vs crashing:
  Decision: conservatively skip big-endian slices in FAT containers and return error.UnsupportedVariant when encountering unexpected variants; prefer conservative error behavior over unsafe parsing.

Key design decisions made
------------------------
- Zero-copy backing buffer model retained: read the full file once and let all BinaryDescription slices point into that single buffer. Ownership is controlled by BinaryBundle.

- BinaryBundle introduced as the owning container for one-or-more BinaryDescription values and the shared backing buffer. This enables returning multiple architecture descriptions (fat binaries) without duplicating file contents.

- SYMTAB-first symbol strategy: parse symbols from LC_SYMTAB (nlist/nlist_64 + strtab) as the pragmatic first step for imports/exports. Export trie/LC_DYLD_INFO parsing is planned for a follow-up (more accurate but more complex).

- Conservative variant support initially: implement and test 64-bit little-endian Mach-O first (most common on macOS), skip big-endian and lesser-used combinations until core architecture is stable.

- Entrypoint translation: use a recorded segment map (fileoff, filesize -> vmaddr) and translate LC_MAIN.entryoff (file offset) to a virtual address using the containing segment. Fallback to the raw file offset if no containing segment is found.
